# Parity Reports

This folder stores parity comparison tables generated by Python fixture tests.

Related knowledge:
- Porting and parity policy decisions: `PORTING.md`
- Test execution and environment commands: `running-tests.md`
- Fixture schema and generation constraints: `fixtures/README.md`

## What Gets Written
Each parity test writes both:
- `<report_name>.csv`
- `<report_name>.md`

In addition, a global aggregate is auto-generated:
- `main_parity_report.csv`

## Column Guide
- `function`: Ported Python function under parity test.
- `case`: Deterministic fixture dataset label (for example `case_1`, `base_c2`).
- `metric`: Compared output block (for example `E`, `covE`, `S`, `G_abck`).
- `max_abs`: Maximum absolute error `max(abs(py - matlab))`.
- `max_rel`: Maximum relative error using denominator clamp:
  `max(abs(py - matlab) / max(abs(matlab), 1e-12))`.
- `atol`, `rtol`: Test tolerances used by `np.allclose`.
- `pass`: Whether the metric passed at those tolerances.

## Main Report Columns
`main_parity_report` groups rows by `function + metric` across all `*_parity_report.csv` files and reports:
- `mean_max_abs`, `std_dv_max_abs`
- `mean_max_rel`, `std_dv_max_rel`
- `mean_abs_over_atol`, `std_dv_abs_over_atol` (scale-aware absolute error pressure)
- `mean_rel_over_rtol`, `std_dv_rel_over_rtol` (scale-aware relative error pressure)
- `n_rows`, `n_reports`, `pass_rate`, `severity_flag`

`severity_flag` values:
- `normal`: no special condition.
- `scale-driven-high-abs`: absolute errors look large, but relative/tolerance-normalized fit stays low and all rows pass.
- `parity-failure`: at least one row failed.

If `main_parity_report.csv` is locked by another process on Windows, the generator writes:
- `main_parity_report.pending.csv`
- `main_parity_report.pending.md`

## How To Read Results
1. Check `pass` first. Any `no` means parity failure for that metric/case.
2. Compare `max_abs` against `atol` for absolute closeness.
3. Compare `max_rel` against `rtol` for scale-aware closeness.
4. Prioritize metrics with large `max_abs`; those usually indicate algorithm drift.

## Important Relative-Error Caveat
`max_rel` uses a `1e-12` denominator floor for stable reporting. When MATLAB reference values are near zero,
`max_rel` can look large even if `max_abs` is tiny and parity is acceptable. In these rows, trust `max_abs` plus the `pass` result more than raw `max_rel` magnitude.

## DX2 Stable1 Finding
For `dx2abck` and `dx2abcdk`, the largest absolute drifts are concentrated in `stable1` mode,
especially matrix `B`. Current parity checks still pass, and percent drift remains low (sub-0.05% in
the observed fixtures), which indicates a scale-driven numeric sensitivity rather than a confirmed
algorithm mismatch.

To summarize hotspots from `dx2_value_comparison.csv`:

```powershell
python python/scripts/summarize_dx2_value_comparison.py
```

This writes:
- `dx2_hotspot_summary.csv`
- `dx2_hotspot_summary.md`

The summary is grouped by `function + mode + matrix` and ranked by `max_pct`.

## Regenerating Reports
From repository root:

```powershell
conda run -n pbsid-py python -m pytest python/tests -q -m parity
```

If tests skip because fixture case count is too small, regenerate MATLAB fixtures first:

```matlab
testutils.generateDvar2eigFixture
testutils.generateDordvarmaxFixture
testutils.generateDmodxFixture
testutils.generateDx2abcFixture
testutils.generateDx2abcdFixture
testutils.generateDvar4varxFixture
testutils.generateDvar2frdFixture
testutils.generateDordvarxFixture
testutils.generateDx2abcdkFixture
testutils.generateDx2abckFixture
```
